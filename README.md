## Repository organization

Every project guide includes prerequisites, numbered steps, command explanations, expected behavior, exact screenshot filenames, troubleshooting, report questions, official references, and a completion checklist.

- `README.md`: guide, purpose, steps, and status
- `screenshots/`: your sanitized evidence and upload instructions
- `reports/findings.md`: your actual observations and conclusions
- `src/`: code you executed or adapted, where relevant (add it during the lab)

## Completion standards

| Status | Meaning |
|---|---|
| Not started | Prepared guide; no execution evidence |
| In progress | Lab underway; actual evidence being collected |
| Completed | All required observations, screenshots, report, and cleanup documented |

Update both the project README and this table as you progress. Keep expected output separate from observed results. A failed or inconclusive test can be valuable evidence when explained honestly.

## Recommended order

Complete 01–06 first. For intermediate work, finish Python basics before 07, permissions and network discovery before 08 and 11, and hash verification before 12. For advanced work, complete log analysis and hardening before 13, forensics before 14, Windows logs before 15, Python and secure-query labs before 16, and incident reporting before 17. Project 18 is a theoretical design exercise and does not need industrial hardware.

## Evidence and scope

Use owned or explicitly authorized disposable systems. Use synthetic fixtures and lab-only identities. Review files and screenshots before publishing; exclude passwords, tokens, private contact information, real account details, unrelated traffic, and personal logs. Do not scan campus, workplace, internet, or industrial systems as part of these exercises.
